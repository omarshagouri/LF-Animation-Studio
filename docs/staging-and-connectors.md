# Private staging and connector verification

## Cloud Run approval and access

Target service: `omar-studio-staging`, region `europe-west1`, in a dedicated Google Cloud staging project. The script builds only the files in `backend/.gcloudignore`. It creates or updates the named service, keeps Cloud Run IAM invocation enabled, and caps staging at one instance. This branch has no automated GCP deployment.

Before running the deployment script:

1. Approve deployment and supply the dedicated staging project ID. Enable billing and `run.googleapis.com`, `cloudbuild.googleapis.com`, `artifactregistry.googleapis.com`, and `secretmanager.googleapis.com` in that project. The bootstrap operator needs permission to enable services and create service accounts, secret resources and IAM bindings.
2. Create separate service accounts `omar-studio-build` and `omar-studio-runtime` in that project. Grant the build account `roles/run.builder` on the staging project. Grant the deployer `roles/run.sourceDeveloper` and `roles/serviceusage.serviceUsageConsumer` on staging, plus `roles/iam.serviceAccountUser` on the two staging service accounts. No production IAM change is required.
3. Create organization-approved Secret Manager resources in the staging project prefixed `omar-staging-`. Start with a random app session token of at least 32 characters. Grant `roles/secretmanager.secretAccessor` to the runtime identity on each individual bound secret. The build identity does not need secret access. Pin numeric versions. Enter actual values through the Secret Manager console or an approved secure secret-loading flow.
4. Optionally add an OpenAI staging-project key with a test budget and verify data retention. Keep Gmail delivery secrets unbound until explicit approval of a synthetic send to a dedicated staging mailbox. Use a separate OAuth grant for delivery (`https://www.googleapis.com/auth/gmail.send`) and keep the fixed sender and recipient in Secret Manager too.
5. Use Bash 4.2+ and a current Cloud SDK. From this checkout, set `STAGING_PROJECT` and `STUDIO_SECRET_BINDINGS` to secret **references** such as `STUDIO_ACCESS_TOKEN=omar-staging-access-token:1`, then run `backend/staging/deploy.sh --approved`. For additional secret references, append comma-separated mappings with numeric versions. The deployment command requires explicit approval.
6. Grant the staging tester `roles/run.invoker` on this service. From an authenticated workstation use `gcloud run services proxy omar-studio-staging --project "$STAGING_PROJECT" --region europe-west1 --port 8080`. Check `GET /health` through the proxy and send only synthetic requests. Use `Authorization: Bearer <studio session token>` for private routes. With direct Cloud Run calls, the Google ID token goes in `X-Serverless-Authorization` and the Studio token remains in `Authorization`.

The native app currently sends only the Studio token. Testing against an IAM-protected Cloud Run service from the phone requires an approved identity-aware access path before connecting native Settings. Keep the service private while this is pending. The public browser disables native credentials and remote API calls.

Staging rate limits and duplicate-mail detection are per process. A restart resets them. Before any production rollout, replace those protections with durable shared state, add audited rotation and retention, and verify application and infrastructure logs contain no meeting content.

## Connector readiness

Provider contracts were checked against Google's discovery definitions. The contracts and tests decode documented response shapes using synthetic values. They intentionally make no external calls. The accounts, actual Sheets columns, AmpCoreX LF/SF schemas, Make zone and scenario response, and YouTube channel configuration have not been inspected.

| Integration | Provider contract and scope | Required before any live connection |
| --- | --- | --- |
| Secretary · Gmail | `users.messages.list` returns `messages[].id/threadId` and `nextPageToken`. Start with Gmail metadata access if ID and header access suffice. Add `gmail.readonly` only when mail content is explicitly approved. [Discovery schema](https://github.com/googleapis/google-api-go-client/blob/main/gmail/v1/gmail-api.json) | Staging Google OAuth consent client and authorized test user. Confirm mailbox and label boundaries, read fields, pagination, and retention. Gmail scopes can require Workspace admin or Google approval. |
| Secretary · Calendar | `events.list` returns `items`, including date-only all-day bounds and timed `dateTime` bounds, and page or sync tokens. Use `calendar.events.readonly` or `calendar.events.owned.readonly` when testing only owned calendars. [Discovery schema](https://github.com/googleapis/google-api-go-client/blob/main/calendar/v3/calendar-api.json) | Dedicated staging calendar and approved calendar selection, timezone, cancelled and recurring event handling. No creates or updates. |
| Padel · Google Sheets | `spreadsheets.values.get` returns `range`, `majorDimension`, and `values`. Use `spreadsheets.readonly` with an OAuth identity or a service account shared as Viewer on an approved synthetic sheet. [Discovery schema](https://github.com/googleapis/google-api-go-client/blob/main/sheets/v4/sheets-api.json) | Verify exact tab, range, headers, team/side representation, numeric and date formats, duplicate key, and consent. Keep identifiers in Secret Manager. Do not request edit access. |
| Padel · screenshot drafts | Authenticated `POST /v1/padel/extract` accepts up to 8 MiB of JPEG or PNG with matching signature. It returns nullable scores and requires human review. It stores no screenshot, creates no match, and makes no Sheets call. | Enable OpenAI only on approved staging, verify device image selection and redaction, run representative synthetic screenshots, and establish false-positive thresholds before wiring the native UI. |
| AmpCoreX · LF/SF | No pipeline transport or field mapping assumed. | Provide non-production read-only sample or data dictionary for both pipelines with stable IDs, stages, timestamps, and deletion semantics. Validate against an approved viewer identity before building a mapping. |
| AmpCoreX · Make | Read-only status preparation only. Provider docs were not reachable from this cloud session. | Administrator supplies the Make zone, staging organization/team, scenario IDs, and current schema or documented read-only permission for the relevant status endpoint. Keep the token in Secret Manager. Do not activate, start, stop, or update scenarios. |
| AmpCoreX · YouTube Analytics | `reports.query` returns `columnHeaders` and `rows`. Use `yt-analytics.readonly` for non-monetary metrics. [Discovery schema](https://github.com/googleapis/google-api-go-client/blob/main/youtubeanalytics/v2/youtubeanalytics-api.json) | OAuth grant from an approved channel owner or manager, staging channel selection, reporting window, metric/dimension compatibility, and owner consent. |

For Google connectors, enable only the relevant APIs in the staging project, create an OAuth consent configuration for testing, register the actual approved callback, and authorize a staging test account. Store the OAuth client ID, client secret, refresh token, and private resource IDs in Secret Manager. Use separate least-privilege grants for reads and mail delivery. The deployment script accepts only credentials consumed by the current backend. Bind read-only OAuth grants only after an approved connector implementation exists.
